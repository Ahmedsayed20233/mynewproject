# Flosy 3.6+ — تنفيذ خارطة الـMVP الذكي (Egypt-first)

**حالة مرجعية: 12 نوفمبر 2026.** هذا مستند تطوير، وليس إعلانًا بإكمال جميع المزايا أو إطلاق المنتج للمستخدمين. لا توجد traction أو اختبارات مستخدمين خارجيين مثبتة. فرع \`main\` تاريخي وغير مستخدم؛ واجهة التطبيق في \`flosy-site\` ونسخة Android في \`flosy-android\`.

## المبادئ التي تميز فلوسي كمشروع قابل للاستثمار
1. **قيمة فعلية خلال أقل من دقيقة**: إنشاء حساب نقدي/بنكي أو محفظة، تحديد العملة EGP، إضافة أول عملية بصوت/صورة/استيراد أو يدويًا، ثم رؤية Safe to Spend حقيقي.
2. **Zero-entry-first** وليس "100٪ بلا خطأ": استيراد اختياري من مصادر موثوقة، تصنيف ومطابقة حساب، وعدم حفظ أحداث OTP/فشل/إلغاء/تعليق. كل معاملة تلقائية لها تراجع Undo وتفسير المصدر.
3. **محلي افتراضيًا**: البيانات المالية والحسابات والرسم والتوصيات تُحلّل على الجهاز ما أمكن. لا نرسل الرسائل أو صور الفواتير لخدمة LLM خارجية تلقائيًا.
4. **مصر أولًا**: العامية المصرية، صيغ الجنيه والقرش، بنوك مصر، InstaPay، محافظ، كاش، جمعيات وأقساط، شهادة ادخار، ذهب، عملة.
5. **لا إخفاء للأخطاء**: المستخدم يعرف مصدر المعلومة، متى تمت المزامنة، وسبب رفض التسجيل التلقائي؛ ولا نعد بمزامنة رسمية مع البنوك من غير اتفاق.

## التصميم المستهدف — MVP
**Home:** شريط Safe to Spend مع تفسيره، إجمالي متاح، 3 حسابات أساسية، التزامات 7/30 يومًا، آخر معاملات مع أيقونة ومصدر، زر مصروف كبير، صوت/كاميرا بنقرة.

**Capture:** شاشة واحدة لمسارات Voice / Receipt / Auto Import / CSV / Manual. تظهر معاينة المبلغ والتصنيف والحساب والمصدر وثقة المطابقة. زر Auto Post مُفعّل افتراضيًا فقط بعد موافقة متعمدة ومعايير ثقة واختبارات. رفض أو احتمال تكرار = صندوق مراجعة.

**Accounts:** كل حساب مستقل برصيد وتاريخ معاملات، اسم وبنك/محفظة وآخر 4 أرقام مخفية، قاعدة مطابقة المصدر. عند غموض الحساب لا تُجرى حركة على أي حساب.

**Insights:** هذا الشهر مقابل السابق، الفئات الأساسية، أسباب الزيادة كـ *ارتباطات لا أسباب مثبتة*، منحنيات يومية، تمرير فترات، محاكاة الادخار، زر Roast اختياري ومحترم.

**Reports:** يوم/أسبوع/14 يوم/شهر/ربع/نصف/سنة/تخصيص + PDF/Excel، تغطية كاملة للحسابات والفئات والتصرفات المحتملة؛ توصيات بلا وعود استثمارية.

**Assistant:** Chat منزلي محلي مقيد بـ Flosy. مجموعة أدوات قراءة فقط: getBalances, getTransactions, comparePeriods, topCategories, assessBills, safeToSpend, createChartSpec. الكلام الحر لا ينفذ قيودًا مالية ولا يحدّث Ledger؛ إضافة عملية تمر بنفس سياسة التحقق.

## خريطة النماذج المحلية الواقعية
1. **Receipt OCR**: لا يصح ادعاء تدريب OCR صور جديد لأن النماذج الحالية تعالج ناتج ML Kit/Tesseract. اجمع موافقات وصور فواتير مصرية من مطاعم وبقالة وصيدلية وأجهزة. افصل train/val/test حسب *المتجر والقالب والجهاز*. جرّب Tesseract Arabic + Latin مع crop/deskew وmodel layout مُقاس، ثم قيّم precision للإجمالي، التاريخ، الصنف، طريقة الدفع والحساب. لا تدريب على فواتير حقيقية دون تصريح.
2. **Speech**: النموذج الحالي VoiceNLU يصنف نصًا ولا يحوّل audio إلى text. اختبر محلّيًا نموذج ASR مناسبًا بالعربي مثل Whisper صغير مُكمّم على أجهزة Android مختلفة، مع Benchmark ضوضاء وسرعة وRAM وحجم APK وترخيص. ثم fine-tune intent/slots على عامية وأرقام مصرية بمجموعات منفصلة عن النصوص الاصطناعية.
3. **Local finance LLM**: يفضّل البدء من نموذج مفتوح صغير متعدد اللغات مُرخّص وقابل للضغط، مع LoRA اختياري *بعد* dataset أسئلة Flosy موثقة. Android llama.cpp / ExecuTorch قد يحتاجان native libs وحزم موديل منفصلة؛ لا يمكن ضمان العمل بلا Benchmark للذاكرة والبطارية. اجعل الأرقام تنشأ حصريًا من أدوات حتمية ويُسمح للنموذج بشرحها؛ وضع Intent Gate يمنع الأسئلة الخارجية، مع اختبارات jailbreak/هلوسة وعدم تعديل دفتر المعاملات.
4. **Auto posting**: لا يُقرر LLM ذلك. عملية حسابية: source trusted && consent && amount valid && direction certain && account unique && event completed && no OTP && no duplicate && confidence calibrated. غير ذلك Review Queue. قياس الأهم: false auto-post per 1,000 imports (الهدف قريب جدًا من الصفر) مع recall وlatency.

## Sprint تنفيذية عملية
**Sprint A — الثبات والشفافية:** تصحيح تقارير الفترة والصافي، Excel متعدد الصفحات، رسومات وتوصيات قابلة للتفسير، أيقونات، اختبارات. *هذا PR v3.6.*
**Sprint B — تجربة الالتقاط:** حسابات متعددة بالـ last4، تعيين البنك من SMS/notification، طابور واحد وإلغاء التكرار.
**Sprint C — OCR / NLU:** إنشاء Corpus مصرح به، مقاييس جودة/مقارنات مع القاعدة الحالية، تحليل أخطاء، اختبار Device.
**Sprint D — Local AI:** صيغة Tool/ChartSpec وقفل نطاق الأسئلة، تنزيل نموذج اختياري، اختبارات RAM/CPU/offline، UX خطأ/استرداد.
**Sprint E — إطلاق تجريبي محدود:** عشرات متطوعين بموافقة، قياس time-to-first-transaction، نسبة الالتقاط بلا تعديل، retention أسبوعي، خطأ الرصيد، تكلفة/مستخدم، crash-free sessions؛ لا ادعاء traction قبل قياسها.

## قبول قبل APK قابل للتجربة
- الموقع: Node + Browser smoke + اختبار تطابق الحقول والحسابات والسجل لكل مصدر؛ ينجح وهو Offline.
- Android: Gradle Standard/Direct، مقارنة الصلاحيات الفعلية، صلاحيات SMS وNotification على هاتف **فعلي**، عدم تعطيل Play Protect، تأكد توقيع APK/نسخ احتياطي قبل تغيير أي نسخة.
- قابلية النشر: إن لم يعمل إذن RECEIVE_SMS، وفّر المسار الخالي من صلاحيات SMS؛ لا تعد بأن Direct Lab يضمن اعتراض الرسائل.
- السرية الدنيا ضرورية حتى في MVP: عدم تسريب OTP أو مفاتيح أو صور فواتير، سحب صلاحية الالتقاط، عدم فقد المال عند التراجع أو المزامنة.

## تقييم المستثمر
أقوى فرضية تستحق الاختبار: «فلوسي يوفر وقت تسجيل المصروفات، وفي الوقت نفسه يقدم نصيحة مفيدة مدعومة بتفاصيل الحساب». المقياس الرئيسي ليس عدد خصائص AI، بل نسبة المعاملات الصحيحة المسجلة تلقائيًا مقابل الأخطاء ونسبة المستخدمين الذين يستمرون في استخدامه أسبوعًا بعد أسبوع. الأرباح والاشتراكات تأتي بعد إثبات القيمة، لا قبلها.
