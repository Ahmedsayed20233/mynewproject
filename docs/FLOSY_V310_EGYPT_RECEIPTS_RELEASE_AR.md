# Flosy v3.10.0 — تطوير فهم الفواتير والإيصالات المصرية

**التاريخ:** 14 نوفمبر 2026  
**الحالة:** Founder-test / ما قبل MVP. لا توجد شهادة دقة قراءة صور عامة، ولا إطلاق تجاري.

## 1. ما تم تنفيذه بالفعل

1. تنزيل ملفات **CORU IE** الحقيقية (Train / Validation / Test) خلال مهمة GitHub Actions موثّقة، وتدريب نموذج **Character-trigram Multinomial Naive Bayes** لتصنيف أسماء المنتجات مع قاموس تقريبي من 2,600 اسم منتج مستخرج من التدريب فقط.
2. توليد **flosy-receipt-coru-model-v310.js** من ملفات البيانات، وليس إنشاء «كلمات مصرية» عشوائية أو أمثلة مفترضة.
3. ضمّ **flosy-receipt-egypt-v310.js** إلى محرك البيانات داخل `index.html` بعد نموذج AraReceipt القديم. يحافظ على النموذج السابق لاختيار الإجمالي ويضيف:
   - تحويل الأرقام العربية والهندية وإعادة تفسير الفصل العشري عند وجود صيغة واضحة.
   - استخراج سطر الصنف من كمية × سعر = إجمالي، مع تحقق جبري قبل قبوله.
   - ربط اسم المنتج المقروء باقتراح CORU دون استبدال كلمات الفاتورة الأصلية من تلقاء نفسه.
   - التحقق من الإجمالي والـSubtotal والضرائب والخصومات والمدفوع والباقي وعدم اعتبار المبلغ المُسَلَّم للكاشير تلقائيًا تكلفةً.
   - تحذيرات عند نقص الأصناف أو تضارب الإجماليات.
4. إصلاح رفع الصور من المعرض بعرض **معاينة للصورة** واستخدام `File` مباشرة عند استدعاء OCR بدل تحويلها إلى Base64 بشكل زائد.
5. رفع الحد الأقصى لصورة Android المشفرة الواردة إلى مسار OCR العربي من 750 KB إلى 11 MB للنص المشفر (مع بقاء حد ملف الرفع المحلي 8 MB)، لتقليل السقوط إلى OCR إنجليزي فقط عندما تكبر صورة الكاميرا.
6. إضافة زر **«استخدم الاسم المقترح»** داخل مراجعة كل صنف؛ لا يتم تعديل الاسم إلا بالضغط.
7. الإبقاء على الحفظ بعد موافقة المستخدم فقط. لا تسجيل آلي للفواتير غير المتحققة.

مهم: الدقة الحالية هي **تصنيف أسماء المنتجات من النص** وليست دقة كاميرا أو تحديد السعر أو نجاح استخراج جميع الفواتير. لم نعد تدريب نموذج ML Kit/Tesseract البصري بعد.

## 3. سلسلة العمل

كاميرا Android/معرض الصور → OCR عربي + إنجليزي الموجود بالفعل → AraReceipt total selector الموجود → CORU item text classifier + name lexicon → تحقق مبلغ/كمية/ضريبة/خصم/مدفوع/باقي → واجهة مراجعة واضحة قابلة للتصحيح → المعاملات عبر الدفتر المالي الموحد.

تظهر تحذيرات إذا كانت الأصناف ناقصة أو إجمالي العناصر مختلفًا؛ يمكن تصحيح الأصناف يدويًا أو حفظ الإجمالي بعد مراجعته. لا حفظ تلقائي.

## 4. البيانات والرخصة

- CORU / ReceiptSense: https://huggingface.co/datasets/abdoelsayed/CORU
- ملفات IE: https://huggingface.co/datasets/abdoelsayed/CORU/tree/main/IE
- تدريب وإثباتات الدقة: `docs/FLOSY_V310_CORU_IE_TRAINING_RESULTS.md`
- التدريب القابل لإعادة الإنتاج: `scripts/train_flosy_coru_ie_v310.py`
- بيانات AraReceipt القديمة: https://huggingface.co/datasets/IslamMesabah/AraReceipt

وسم CORU الحالي وREADME يذكران MIT؛ احتفظ بالنسبة للمصدر وتحقق من شروط الصور والملفات المحددة قبل أي إطلاق تجاري. لم يتم تضمين صور العملاء أو ملفات المجموعة الخام داخل APK؛ النموذج عبارة عن معاملات/قاموس صغير نسبيًا فقط.

## 5. الاختبارات وحدود الإثبات

- `tests/v310-coru-receipts.test.cjs`: تدريب CORU، فحص بيانات النموذج، أسماء المنتجات، الأرقام العربية، القيم المالية، الضرائب والباقي والحفظ الآمن.
- `tests/v310-browser.cjs`: اختبار 390px في Chromium لفتح صفحة الفاتورة، واستيراد صورة PNG اصطناعية محلية، وحقن نص OCR تجريبي فقط، والمرور عبر النموذج المدرب وشاشة المراجعة مع التحقق من عدم تسجيل المال تلقائيًا.
- الاختبارات القديمة للشاشات والذكاء والصوت والميزانية وسجل المعاملات يجب أن تستمر بنجاح.
- اختبار الكاميرا والميكروفون والسرعة على هاتف Android حقيقي لم يُجرَ بعد.
- اختبار Chromium للصورة **لا يقيس دقة OCR الحقيقي** لأنه يستخدم نص OCR معلومًا كمدخل في هذا الاختبار، بينما يتم فحص جزء المحاسبة والمراجعة فعليًا.
- النسخة Android تعتمد على GitHub Pages عبر WebView؛ نشر `flosy-site` يجب أن يسبق نشر APK. آخر فرع موقع يعمل بوضع v3.10.0.

## 6. الخطوات العلمية التالية لتطوير OCR الصورة نفسه

1. تحميل وتدقيق CORU `OCR/{train,val,test}.zip` (259 MB تقريبًا)، التحقق من النص والصورة والحقوق وتداخل الإيصالات مع AraReceipt.
2. قياس Tesseract العربي/الإنجليزي وPaddleOCR العربي على **عينات صور مستقلة** وإنشاء CER/WER، واختبار صور موبايل حقيقية.
3. Fine-tune نموذج تعرف بصري خفيف بإعدادات قابلة لإعادة الإنتاج ومنع تسرّب الإيصالات بين التدريب والاختبار.
4. تدريب محدد الحقول في الصورة مع رسائل الثقة المعيارية وقياس grand-total exact-match بدل الاعتماد على دقة أسماء المنتجات.
5. مجموعة صور مصرية موافق عليها، متوازنة بين سوبرماركت وصيدليات وكافيهات وفواتير مرافق وغيرها، مع اختبار مستقل من متاجر غير مستخدمة في التدريب.
6. لا يُفعَّل الحفظ التلقائي للفواتير قبل التحقق الصارم من إجمالي الفاتورة والحساب وتقييم الأخطاء المالية ووجود التراجع.

## 7. حالة إصدار Android

الإصدار المستهدف **3.10.0**، معرّف الاختبار `com.flosy.finance.unified.v3100`، نسخة Debug/Fouder test فقط. اختلاف الحزمة يعني أن البيانات المحلية للإصدارات السابقة لا تنتقل تلقائيًا.
