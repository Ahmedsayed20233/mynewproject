## Architecture and data flow

- `index.html` is the Arabic RTL app shell and canonical ledger UI.
  `flosy-assistant-bridge.js` exposes shared state/actions; `finance-pro.js`
  supplies account/wealth calculations. Numerous layered static modules make
  script ordering and duplicate UI paths maintenance risks; retain the existing
  architecture and protect it with integration tests.
- `flosy-phase1.js:calculate` computes discretionary Safe-to-Spend from actual
  free account cash less protected bank funds, unpaid obligations, remaining
  fixed/variable budgets and buffer. Future salary appears in forecast scenarios,
  not current cash. Completeness of recorded obligations remains an input risk.
- Capture: Android image -> Latin ML Kit plus downscaled image -> web Tesseract
  Arabic/English -> `flosy-receipt-ml.js` structured text extraction ->
  `flosy-v4-capture.js` proposal/account/opt-in/dedup -> ledger or editable review.
  `flosy-repair.js` owns capture UI. Tesseract is loaded at 7.0.0; language packs
  may need network on first use. The 14,000-example ranker is synthetic text
  training, not image recognition accuracy evidence.
- Voice: Android on-device-preferred SpeechRecognizer (`ar-EG`, OS fallback)
  or browser recognition -> local VoiceNLU -> canonical capture. The 14,800
  synthetic utterances train transcript intent only. Existing guards reject
  future/negated/question/internal-transfer phrases; physical STT quality is unknown.
- SMS: share/paste or independently authorized Automate -> token-authenticated,
  sender-allowlisted native receiver -> AES-GCM AndroidKeyStore queue -> web relay
  and parser. Native queue capture is not itself ledger posting. Source tests
  include legacy “review-only” assertions while current integration tests prove
  opt-in posting; wording must be reconciled before simplifying onboarding.
- `flosy-sync-v3.js` uses revision CAS RPC, tombstones, ID/stamp merge, local
  recovery copies and pending state. Scalar conflicts prefer remote values;
  this deserves explicit two-device tests. `flosy-v5-private-backup.js` uses
  AES-256-GCM, PBKDF2-SHA256 (250,000 iterations), owner checks and explicit
  restore. Local storage is not encrypted at rest. SQL includes ownership RLS;
  deployed policies and credentials were not inspected.
- Gemini gateway source uses owner JWT, enable flag, atomic 12/day quota and a
  restricted label/rounded-band payload. It does not prove model availability,
  free-tier eligibility, actual billing state or production reliability. Keep
  existing paid fallback disabled; no AI requests were made.
- Android WebView loads the hosted site, not a bundled current frontend. Native
  bridge checks main frame, HTTPS origin and current app path. File access is
  disabled; scoped content access supports images. Compile/target SDK 35, min 24,
  AGP 8.9.2, Java 17, ML Kit 16.0.1, core 1.15.0, WebKit 1.13.0. v3.4.0/code 34
  flavors: `com.flosy.finance` and `com.flosy.finance.sms`.

## Verified bugs and delivery risks

1. **P0 fixed in this branch:** subtotal 100 + VAT 14 with printed grand total
   914 returned confidence .98 and `autoQuality:true`. No arithmetic check existed.
   The fix vetoes auto-post on a printed subtotal mismatch and explains review.
2. **P0 remaining:** `FLOSY_CAPTURE.isDuplicate` checks a source hash or identical
   account/type/date/amount/description. Different SMS/voice/receipt descriptions
   and source hashes can evade cross-source dedup. Do not broaden matching to
   amount/date alone, which could suppress genuine repeated purchases.
3. **P0 remaining:** physical camera rotation, Arabic pack availability, OS speech,
   lifecycle/queue delivery, two-device CAS conflicts and backup recovery are
   unverified. Synthetic tests cannot sign off an Android production release.
4. **P1 deployment/documentation:** only quality and browser workflows exist in
   the fetched site tree. README references an absent `publish-flosy.yml` and
   contains contradictory historical SMS, sync, hosting and paid-AI descriptions.
   Handoff reports prior Pages success; actual Pages settings/deployment source
   could not be verified. Do not add a deployment workflow without reviewing them.
5. **P1 native release:** workflow builds two debug APKs and on production-branch
   pushes uploads/clobbers the v3.4.0 release assets. Debug signing is not stable
   release signing. Preserve occupied installs until independent backup recovery
   is verified. No APK release was built or published here.
6. Open drafts #17/#20/#22/#25/#26 could not be inventoried: GitHub CLI GraphQL
   and REST network access are forbidden in this environment. No PR was merged
   or closed, and none is assumed superseded.
